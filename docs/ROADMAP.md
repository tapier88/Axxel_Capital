# Roadmap por dependencias

**AHORA: PHASE_1_FOUNDATION, G3 + G4.** No cambiar de fase en esta publicación.
Control Tower solo después de revisión del gate Foundation y aprobación posterior.

| Fase | Entregable / dependencia |
|---|---|
| 1 FOUNDATION | Ruta histórica G3, cualificación G4, contratos y evidencia G1…G6; certificación fuerte separada |
| 2 CONTROL | Control Tower, permisos y lifecycle; bloqueada por Foundation |
| 3 OBSERVABILITY | Trazas/evaluación operativa; depende de control |
| 4 EXPERIENCE | Integración de experiencia auditable; depende de evaluación |
| 5 LEARNING | Lecciones reproducibles; depende de experiencia confiable |
| 6 IMPROVEMENT | Comparación champion/challenger; depende de métricas |
| 7 ARCHITECTURE EVOLUTION | Gaps demostrados y cambios revisados |
| 8 AUTONOMY | Menor intervención con seguridad no degradada |
| 9 PAPER/DEMO | Ejecución demo con permisos, watchdog y costes observados |
| 10 PRODUCTION CANDIDATE | Evidencia, riesgo, rollback y aprobación explícita; nunca promoción automática |

Los epics P0–P13 del backlog son desglose de trabajo; no cambian las diez fases del master.
La publicación GitHub habilita colaboración/reproducción de software, no mercado/research.
No construir Generalist Intelligence, Mission Control ni otro Data Engine para eludir G3/G4.
